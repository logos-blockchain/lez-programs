# Oracle module

`oracle_module` is a headless universal Logos core module. Its Qt-free C++
implementation normalizes identities, reads live public accounts, calls the
stateless `oracle_ffi` Rust library, and submits validated plans through
`lez_core`. Plugin and interface glue are generated by logos-module-builder.
There is no QML dependency and the module does not open, configure, or close a
wallet. The host owns the wallet lifecycle.

The initial producer is `programs/twap_oracle`. Canonical price validation is
separate from TWAP address discovery and instruction planning: other producers
can use the existing `OraclePriceAccount` layout without adopting TWAP state.
No alternative price layout or provider plugin system is introduced.

## Implemented API

All public methods return a `LogosMap` with either
`{"status":"ok","error":"",...}` or
`{"status":"error","error":"<stable_code>"}`. The module exports three
discovery methods (below), two [canonical price
reads](#canonical-price-reads), and six [transaction
methods](#transactions), one per TWAP oracle instruction. The tick and
observation readers in the [roadmap](#api-roadmap-and-dependency-order) are
not implemented yet.

### `setOracleProgramId({oracleProgramId})`

Select the oracle **program id** — the TWAP oracle binary's RISC Zero ImageID —
in base58 or 64-character hex. Hex is normalized to lowercase. A nonempty selection overrides
`TWAP_ORACLE_PROGRAM_ID` for this module instance. `""` clears that override and
restores the current environment fallback. Success returns the public success
envelope. Missing/non-string input returns `bad_request`. Invalid nonempty input
returns `invalid_program_id` and preserves the previous selection.

### `programInfo()`

Resolve the active configuration on each call, without a permanent discovery
cache. Returns:

| Field | Meaning |
| --- | --- |
| `programId`, `programIdHex` | Program id (ImageID), base58 and lowercase hex |
| `imageIdHex` | The same ImageID in lowercase hex; on LEZ v0.2.4 the program id *is* the ImageID |
| `clockId`, `clockIdHex` | Canonical `CLOCK_01` address, base58 and lowercase hex |

The program id comes from the selection above, else `TWAP_ORACLE_PROGRAM_ID`, else
the ImageID of `TWAP_ORACLE_PROGRAM_BIN` (a deployable RISC Zero binary, reread on
every call). With both an id and a binary, they must agree. Neither returns
`config_missing`; an unreadable/invalid binary returns `invalid_program_binary`;
an id that differs from the binary's ImageID returns `program_binary_mismatch`.
Discovery performs no account reads.

### `feedAddresses({priceSourceId, windowDurationMs})`

Normalize the source's base58/hex address and derive these pairs using the core
crate's helpers and the currently selected program id:

- `currentTickAccountId` / `currentTickAccountIdHex`
- `priceObservationsId` / `priceObservationsIdHex`
- `priceAccountId` / `priceAccountIdHex`
- `clockId` / `clockIdHex`

`windowDurationMs` is an exact decimal string, at least `OBSERVATIONS_CAPACITY`
(currently `2048`). A smaller window returns `invalid_window`. A source has one
current-tick address shared across windows; each source/window has separate
observations and price addresses. Base and quote assets are stored data, never
PDA seeds. Derivation does not establish account existence or initialization.

## Canonical price reads

Both reads take explicit account and owner ids, so they work without any TWAP
program configuration and never consult the selected deployment. Rust owns
validation; C++ normalizes ids, fetches current state through `lez_core` on
every call, and passes provider snapshots only — caller-supplied account bytes
never reach the FFI. Reads sign and submit nothing.

### `priceAccount({priceAccountId, expectedOwnerId})`

Returns the stored canonical snapshot verbatim. Zero prices, zero timestamps,
and stale data are data, not errors: usability is the consumer's policy.

| Field | Meaning |
| --- | --- |
| `priceAccountId` / `...Hex` | The exact account that was read |
| `ownerId` / `...Hex` | Owning program (ImageID) from the snapshot |
| `baseAssetId`, `quoteAssetId`, `sourceId` (+ `...Hex`) | Stored identities |
| `price`, `timestampMs`, `confidenceInterval` | Exact decimal strings; `price` is stored Q64.64 |
| `priceFractionalBits` | Always `64` — the real price is `price / 2^64` |

### `queryPrice({priceAccountId, expectedOwnerId, baseAssetId, quoteAssetId, expectedSourceId, maxAgeMs})`

The same read plus the caller's consumer policy. The canonical `CLOCK_01`
account is fetched internally on every call — its address comes from a
configuration-free FFI, not from `programInfo` — and validation fails closed:
a usable price is never returned after any check fails. Checks run in order:

| Check | Error |
| --- | --- |
| Account read, id, existence, owner, exact Borsh | `account_read_failed`, `price_account_id_mismatch`, `not_found`, `oracle_owner_mismatch`, `invalid_account_data` |
| Base and quote assets match | `oracle_asset_mismatch` |
| Source matches | `oracle_source_mismatch` |
| Price nonzero | `oracle_price_zero` |
| Timestamp nonzero | `oracle_timestamp_zero` |
| Clock readable and canonical | `account_read_failed`, `invalid_clock` |
| Stored timestamp no later than the canonical clock | `oracle_future_timestamp` |
| `ageMs <= maxAgeMs` — age exactly at the limit is valid | `oracle_stale` |

The response is the `priceAccount` snapshot plus `checkedAtMs` (the canonical
clock timestamp read for this call) and `ageMs`, as exact decimal strings. A
TWAP discovery-to-query journey:

```text
addresses ← feedAddresses({priceSourceId, windowDurationMs})
queryPrice({priceAccountId: addresses.priceAccountId,
            expectedOwnerId: <trusted oracle ImageID>,
            baseAssetId, quoteAssetId,
            expectedSourceId: priceSourceId,
            maxAgeMs: <consumer freshness limit>})
```

## Transactions

Each method plans one TWAP oracle instruction in Rust (PDAs, argument checks,
instruction words, signer flags), checks the accounts it touches on-chain, and
submits through `lez_core`. Arguments are decimal strings; account ids are
base58 or hex. Prices are Q64.64 (`18446744073709551616` = 1.0, quote per base).

| Method | Request | Signs | Requires |
| --- | --- | --- | --- |
| `createCurrentTickAccount` | `{priceSourceId, initialPrice}` | source | current tick absent |
| `createPriceObservations` | `{priceSourceId, initialTick, windowDurationMs}` | source | observations absent |
| `createOraclePriceAccount` | `{priceSourceId, baseAssetId, quoteAssetId, initialPrice, windowDurationMs}` | source | price account absent |
| `updateCurrentTick` | `{priceSourceId, price}` | source | current tick exists |
| `recordTick` | `{priceSourceId, windowDurationMs}` | nobody | observations and current tick exist |
| `publishPrice` | `{priceSourceId, windowDurationMs}` | nobody | observations, price account and current tick exist |

- **Source writes** (the first four) need `priceSourceId` to be a public account
  in the wallet: it signs. A missing or private source returns
  `source_not_signable`.
- **Maintenance** (`recordTick`, `publishPrice`) is permissionless and submits
  with no signer.
- **Account checks.** A creation whose target already exists (any non-default
  account) returns `already_initialized`. An account that must exist but is
  default, or is owned by another program, returns `account_not_initialized`. A
  failed read returns `account_read_failed`. These mirror the program's own
  checks, so callers get a stable code instead of a transaction that fails
  on-chain.
- **Arguments.** `windowDurationMs` below 2048 (`OBSERVATIONS_CAPACITY`) returns
  `invalid_window`; a zero `initialPrice` for `createOraclePriceAccount` returns
  `invalid_price` (zero is the "no valid price" sentinel). `initialTick` is a
  signed `i32`.
- **Results.** Success returns `transactionId` plus the operation's account ids
  (base58 and `...Hex`): `priceSourceId`, `clockId`, and whichever of
  `currentTickAccountId`, `priceObservationsId`, `priceAccountId`, `baseAssetId`,
  `quoteAssetId` it touches.

A feed is set up in this order: `createCurrentTickAccount`, then per window
`createPriceObservations` and `createOraclePriceAccount`. After that the source
calls `updateCurrentTick` whenever its price changes, and anyone calls
`recordTick` and `publishPrice`. The program applies some instructions as
no-ops, and they still succeed:

- `recordTick` skips a sample taken sooner than `windowDurationMs / 2048` after
  the previous one.
- `publishPrice` writes nothing until the window has two observations (the
  creation sample plus one `recordTick`).

A `transactionId` means the sequencer accepted the transaction, not that it
changed state; read the accounts to confirm.

## Wire and validation contracts

Account identities have a base58 field and a lowercase-hex `...Hex` field in
public results. C++ normalizes inputs before calling Rust; the internal FFI
accepts canonical lowercase 32-byte hex only. Zero is not a selectable program
or request account, but the default owner is valid inside an account snapshot.

Numeric inputs and outputs use **decimal strings**, never floating-point JSON
numbers. Unsigned prices/confidence intervals use `u128`; timestamps, durations,
windows, ages, and counters use their core unsigned range (up to `u64::MAX`).
Unsigned text contains digits only and rejects either sign. Signed ticks (`i32`)
and tick cumulatives (`i64`) permit a leading `-` and reject `+`. Fractions,
scientific notation, whitespace, and overflow are rejected. Numeric text errors
return `invalid_numeric_value`; a non-string/missing discovery field is a
`bad_request`. Leading zeroes are accepted without changing the value.

Canonical prices use **Q64.64**, identified by `priceFractionalBits: 64` in
price responses. The real price is `price / 2^64`, quote units per base
unit. `18446744073709551616` means unity. Timestamps and durations are
**milliseconds**. The module does not infer token decimals, invert a price, or
convert it to a consumer's fixed-point scale. A zero confidence interval means
the source supplies no interval, not certainty.

`oracle_module_support::publicAccountRead` converts `lez_core.get_account_public`
results into the internal Rust `AccountRead` shape:

```json
{
  "id": "<canonical account hex>",
  "status": "ok",
  "account": {
    "program_owner": "<32-byte hex>",
    "balance": "<16-byte little-endian hex>",
    "nonce": "<16-byte little-endian hex>",
    "data": "<even-length hex>"
  }
}
```

A transport `logos::CallError`, an empty response, or malformed account JSON/hex
produces `status: "account_read_failed"` without an `account`. A valid default
snapshot (zero owner, balance, nonce, and empty data) remains `status: "ok"`
with the complete snapshot. Rust distinguishes failed reads, `Account::default()`,
and initialized accounts. Empty responses never imply `not_found`.

The shared Rust clock validator requires `CLOCK_01_PROGRAM_ACCOUNT_ID` and exact
`ClockAccountData` Borsh decoding, rejecting trailing bytes. A failed read stays
`account_read_failed`; a readable wrong-address or malformed clock returns
`invalid_clock`.

`api::price::validate_price_account` is a producer-independent typed Rust helper:
it checks the supplied address, default state, expected owner, and exact existing
`OraclePriceAccount` layout. Its typed outcomes are not yet public module error
codes. It imposes no TWAP PDA, freshness, fallback, or aggregation policy.

### FFI ownership

The `oracle_ffi` crate builds `cdylib` and `rlib` outputs. Its typed Rust discovery
API is re-exported at the crate root. C entry points accept NUL-terminated UTF-8
JSON and return allocated UTF-8 JSON:

| C function | Request |
| --- | --- |
| `oracle_program_info` | `{oracleProgramId?, elf?}` |
| `oracle_feed_addresses` | `{oracleProgramId, priceSourceId, windowDurationMs}` |
| `oracle_create_current_tick_account_plan` | `{oracleProgramId, priceSourceId, initialPrice}` |
| `oracle_create_price_observations_plan` | `{oracleProgramId, priceSourceId, initialTick, windowDurationMs}` |
| `oracle_create_oracle_price_account_plan` | `{oracleProgramId, priceSourceId, baseAssetId, quoteAssetId, initialPrice, windowDurationMs}` |
| `oracle_update_current_tick_plan` | `{oracleProgramId, priceSourceId, price}` |
| `oracle_record_tick_plan`, `oracle_publish_price_plan` | `{oracleProgramId, priceSourceId, windowDurationMs}` |
| `oracle_free` | The pointer returned by this library; null is accepted |

`elf` is hex-encoded binary data. Envelopes
match sibling FFIs: `{"ok":true,"value":{...}}` or
`{"ok":false,"error":"<code>"}`. Unknown request fields and malformed requests
are rejected. Rust panics are caught before crossing C; they return
`backend_error`. Each returned pointer must be released exactly once with
`oracle_free`, never the host's allocator. `include/oracle_ffi.h` is generated by
cbindgen. C++ uses RAII to free successful and failed responses.

## Shared transaction architecture

The transaction methods share one path. Each `oracle_*_plan` returns
`{plan, identities}`; C++ checks that the plan targets the resolved program and
that every identity's base58 and hex spellings agree, runs the account checks
above, then submits. There is no public raw-plan or submission method:
applications cannot supply their own accounts, instruction bytes or signer
flags.

A plan contains `programId` (hex), ordered `accountIds` (hex), equally sized
`signingRequirements` (booleans), and `instruction` (`risc0_zkvm::serde::to_vec`
words, each a `u32`) — the guest's instruction encoding on LEZ v0.2.4. Three- and
four-account plans are supported. The C++ transport flattens the words
little-endian into the byte payload `lez_core` expects. `api::twap::TransactionPlan` constructs production signer
flags from the typed instruction:

| Operations | Account order | Instruction signers |
| --- | --- | --- |
| Three source-authorized creations; current-tick update | `[target, price_source, CLOCK_01]` | `[false, true, false]` |
| Record tick | `[observations, current_tick, CLOCK_01]` | `[false, false, false]` |
| Publish price | `[observations, price, current_tick, CLOCK_01]` | `[false, false, false, false]` |

The shared C++ transport validates structure and forwards flags unchanged; it
does not assume the source is at index 1. Tests also pass a signer at index 0.
Operation planners remain responsible for validating account identities, owners,
contents, and instruction arguments before constructing a plan.

The common adapter:

1. Reads wallet inventory through `lez_core.list_accounts`. Only entries with
   `is_public == true` are signable. A failed/malformed inventory returns
   `backend_error`; a missing instruction signer returns `source_not_signable`.
2. Forwards the account order, flags, and byte payload to
   `lez_core.send_generic_public_transaction`.

LEZ v0.2.4 charges no transaction fees, so there is no fee payer: permissionless
maintenance submits with no signer at all.

Success returns `{"status":"ok","error":"","transactionId":"...",...}`
plus the operation's named account identities. The transaction ID must be exactly
64 lowercase hex characters. Transport errors, failed replies, and invalid
transaction hashes return `wallet_submission_failed`. Submission acceptance is
not execution, a changed account, or finality. Sampling/publication may validly
leave accounts unchanged.

## Stable errors

`oracle_module_support::stableFfiError` is a **closed allowlist**. Every other
code maps to `backend_error`; raw Rust/provider diagnostics are never public
errors. New domain codes must be added to the allowlist before they are
returned.

| Category | Codes |
| --- | --- |
| Request and numeric input | `bad_request`, `invalid_account_id`, `invalid_numeric_value`, `invalid_window`, `invalid_price` |
| Deployment | `config_missing`, `invalid_program_id`, `invalid_program_binary`, `program_binary_mismatch` |
| Reads and clock | `account_read_failed`, `invalid_clock` |
| Canonical price reads | `price_account_id_mismatch`, `not_found`, `oracle_owner_mismatch`, `invalid_account_data`, `oracle_asset_mismatch`, `oracle_source_mismatch`, `oracle_price_zero`, `oracle_timestamp_zero`, `oracle_future_timestamp`, `oracle_stale` |
| Account state | `already_initialized`, `account_not_initialized` |
| Authority | `source_not_signable` |
| Transport/internal | `wallet_submission_failed`, `backend_error` |

## API roadmap and dependency order

All work targets the `lez-v0.2.x` line (LEZ v0.2.4) and its dependency pins. The
issues were written for LEZ v0.2.5; on v0.2.4 their `feePayerId` arguments and
loader-header checks do not apply.

Issues 01, 02 and 04–07 are implemented here; 03 and 08 are not.

| Issue | API/deliverable | Prerequisites |
| --- | --- | --- |
| [01 / #437](https://github.com/logos-blockchain/lez-programs/issues/437) | `setOracleProgramId`, `programInfo`, `feedAddresses`; shared contracts | Done |
| [02 / #438](https://github.com/logos-blockchain/lez-programs/issues/438) | `priceAccount({priceAccountId, expectedOwnerId})`; `queryPrice` additionally takes `baseAssetId`, `quoteAssetId`, `expectedSourceId`, `maxAgeMs` | Done |
| [03 / #439](https://github.com/logos-blockchain/lez-programs/issues/439) | `currentTick({priceSourceId})`; `priceObservations({priceSourceId, windowDurationMs})` | 01 |
| [04 / #440](https://github.com/logos-blockchain/lez-programs/issues/440) | `createCurrentTickAccount`, `createPriceObservations`, `createOraclePriceAccount` | Done |
| [05 / #441](https://github.com/logos-blockchain/lez-programs/issues/441) | `updateCurrentTick({priceSourceId, price})` | Done |
| [06 / #442](https://github.com/logos-blockchain/lez-programs/issues/442) | `recordTick({priceSourceId, windowDurationMs})` | Done |
| [07 / #443](https://github.com/logos-blockchain/lez-programs/issues/443) | `publishPrice({priceSourceId, windowDurationMs})` | Done |
| [08 / #444](https://github.com/logos-blockchain/lez-programs/issues/444) | Complete direct-source, AMM, keeper, and consumer journeys | 02–07 + [Stablecoin scale normalization #445](https://github.com/logos-blockchain/lez-programs/issues/445) |

The transaction methods landed without the readers from 03: their account
checks use plain account reads, not decoded TWAP state. Canonical price
reads work independently of selected TWAP configuration. The read APIs select neither a primary feed nor a fallback.

Source authority belongs to the source account: direct writes require its
wallet signature. AMM pool PDAs retain authorization through existing AMM chained
calls; a wallet user cannot impersonate the pool. `oracle_module` depends only
on `lez_core`, never on `amm_module` or `stablecoin_module`. Applications own feed
selection, polling, keeper scheduling, display formatting, fallback/divergence
policy, and composition. Each source's price is exposed separately.

The current TWAP program has exactly six instructions. This series adds no global
initialize/register-feed instruction, pair-only PDAs, configurable cardinality,
governance setters, external-feed relay, scheduling service, or UI.

## Build and headless use

From the repository root:

```sh
nix build .#oracle_ffi .#oracle-module .#oracle-module-tests
RISC0_DEV_MODE=1 cargo test -p oracle_ffi
```

Like the other modules, `modules/oracle` is also a self-contained flake (it takes
`oracle_ffi` from the root flake via `lez_programs`), so it builds standalone
from its own directory.

Module-specific aliases are `oracle-module-lgx`, `oracle-module-lgx-portable`,
`oracle-module-install`, and `oracle-module-install-portable`. The module's local
flake pins the same `lez_core` as the root flake.

Use the development `logoscore` runtime with development module builds (or the
portable runtime with portable modules). Inspect the generated plugin, then
start a headless daemon with both `oracle_module` and `lez_core` available in its
installed module directories. These contain each module's `manifest.json` and
`variant`, not just loose shared libraries:

```sh
nix build .#oracle-module-install --out-link target/oracle-module-install
export TWAP_ORACLE_PROGRAM_ID='<oracle program id (ImageID)>'
lm methods '<plugin path>/oracle_module_plugin.so' --json
logoscore --modules-dir target/oracle-module-install/modules \
  --modules-dir '<lez_core installation>/modules' daemon
```

From another terminal using the same host configuration:

```sh
logoscore load-module oracle_module
logoscore call oracle_module programInfo
logoscore call oracle_module feedAddresses \
  'json:{"priceSourceId":"<source address>","windowDurationMs":"60000"}'
```

Setting up and running a feed for a source account held by the host's wallet
(price 1.0, one-day window):

```sh
logoscore call oracle_module createCurrentTickAccount \
  'json:{"priceSourceId":"<source>","initialPrice":"18446744073709551616"}'
logoscore call oracle_module createPriceObservations \
  'json:{"priceSourceId":"<source>","initialTick":"0","windowDurationMs":"86400000"}'
logoscore call oracle_module createOraclePriceAccount \
  'json:{"priceSourceId":"<source>","baseAssetId":"<base>","quoteAssetId":"<quote>","initialPrice":"18446744073709551616","windowDurationMs":"86400000"}'
logoscore call oracle_module updateCurrentTick \
  'json:{"priceSourceId":"<source>","price":"18446744073709551616"}'
logoscore call oracle_module recordTick \
  'json:{"priceSourceId":"<source>","windowDurationMs":"86400000"}'
logoscore call oracle_module publishPrice \
  'json:{"priceSourceId":"<source>","windowDurationMs":"86400000"}'
```

Discovery needs no source authority; the source writes need the source's key in
the wallet. The host supplies `lez_core`.
The test package uses the generated dependency API and mocks transport/FFI
failures, and Rust tests use the built TWAP guest for ImageID checks.
Repository formatting, lint, unit/integration, guest, and IDL checks remain the
validation gates in the current CI configuration.
